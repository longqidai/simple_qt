# simple_qt

基于 Qt 5.14.2 的 Windows SLAM 标定上位机。程序负责机械臂任务编排、设备 Wi-Fi 连接、设备信息读取、MQTT 采集控制、FTP 数据下载和槽位结果记录。

## 当前流程

1. 连接 GRR20 机械臂并完成 `$$MT,CONNECT` 握手。
2. 选择左右 2×3 托盘槽位。
3. 机械臂扫码并上报设备 SN；设备暂留托盘，上位机不立即发送 `$$MT,START`。
4. 上位机根据 SN 连接设备 Wi-Fi、读取设备信息、连接 MQTT，等待 `init_ready=1`，并创建扫描工程和任务。任一步失败都会把当前槽位标红并直接扫描下一设备，不抓取也不放回。
5. 创建扫描任务后先发送带任务 ID、母工程 ID 的 `ModelingRequest(AC_PREINIT)`，再发送 `data_collect AC_START`。只有收到 `collecting`、确认采集目录创建成功后，上位机才发送 `$$MT,START` 允许机械臂抓取。
6. 机械臂从扫码点安全抬高，移动到抓取点夹取设备，携带设备返回 `P41/Home` 静置并上报 `$$MT,HOMEOK`。
7. 原始采集和 `HOMEOK` 都已就绪后，上位机发送 `ModelingRequest(AC_START)`。只有设备进入 `EC_ScanScanning` 才表示传感器真正打开并开始扫描；如果设备返回 `preinit required`，程序会再次执行 `AC_PREINIT` 后有限次重试。
8. 设备进入 `EC_ScanScanning` 后，上位机发送 `$$MT,SCANREADY`；机械臂回复 `$$MT,SCANREADYOK` 后才离开 Home 执行 SLAM 轨迹，完成后上报 `$$MT,RUNFINISH`。
9. 机械臂上报运动完成且设备已进入真实扫描后，发送 `ModelingRequest(AC_STOP)` 并等待设备保存扫描工程，再停止标定原始数据记录。
10. 保存该设备的 SN、Wi-Fi 和采集目录，立即通知机械臂放回设备并处理下一槽位。
11. 所有槽位测量、采集和放回完成后结束机械臂流程。
12. 上位机按 SN 逐台重连设备 Wi-Fi，通过 FTP 统一下载全部采集数据。

`data_collect` 只负责标定原始数据记录，单独调用不会进入设备完整扫描流程。程序还必须启动 `modeling`。设备联网和任务准备可以与机械臂夹取并行，但真实扫描初始化必须等机械臂携带设备回到 Home 静置；真实扫描就绪后才释放机械臂标定轨迹。

若设备返回 `error=3 / failed to create collect dir`，表示设备端文件或目录操作失败。由于此时机械臂尚未抓取，上位机会直接将当前槽位标记失败并扫描下一设备，不执行无意义的抓取和放回。该错误通常表示设备存储未挂载、剩余空间不足或文件系统只读，需要在设备端处理。

设备 Wi-Fi 状态采用连续检测去抖，短暂一次扫描不到热点不会立即判定断线；MQTT 发生瞬时中断时会重新连接、重新订阅，并恢复可安全重发的采集控制指令。

## 异常停止保护

一旦上位机已经发送原始采集或真实扫描的 `AC_START`，程序会把设备视为“可能仍在测量”。此后遇到步骤超时、协议错误、Wi-Fi/MQTT 断线、机械臂断线、人工中止或其他槽位失败时，不会立即切换下一槽位：

1. 保持当前设备和槽位，自动重连设备 Wi-Fi 与 MQTT。
2. 重复发送 `ModelingRequest(AC_STOP)`，直到收到扫描状态 7/8/9 或设备明确回复扫描已停止。
3. 重复发送 `data_collect AC_STOP`，直到设备明确回复 `collect stopped`、`not active` 或 `already stopped`。
4. 两部分均确认停止后，才通知机械臂放回设备，并中止任务或继续下一槽位。

停止确认阶段每 8 秒重连并重发一次停止指令，正常收到“已停止 / no collect session / 状态 7、8、9”等确认后立即完成收尾。连续 6 次仍无法确认时，上位机会结束本地工作流并恢复连接、重新开始等操作能力，同时在界面保留“未收到停止确认”的安全警告；再次操作前必须人工确认设备已经停止测量。测量期间点击窗口关闭按钮也会先触发同一套安全中止流程。操作系统强制结束进程、电脑断电或设备完全失联无法由上位机软件单独保证，正式产线还应配置设备侧扫描超时/看门狗作为最后保护。

每次开始任务以及异常收尾都会更新工作流代次。旧任务遗留的 MQTT 重连、Wi-Fi 延时、采集恢复和槽位切换回调会被自动丢弃，不能再修改新任务状态。任务运行期间连接按钮被锁定；应先通过“中止任务”完成安全收尾，再断开或重新连接机械臂。

槽位状态：蓝色待处理、橙色测量中、紫色等待统一下载、天蓝色下载中、绿色成功、红色失败。

## 依赖

- Windows 10/11
- Qt 5.14.2 MinGW 64-bit
- MinGW 7.3 64-bit
- Qt MQTT 5.14.2
- 系统 `curl`（用于 FTP 下载）

不依赖 OpenCV。机械臂使用 VX500 视觉项目完成 SN 扫码。

## qmake 构建

```powershell
D:\Qt\Qt5.14.2\5.14.2\mingw73_64\bin\qmake.exe simple_qt.pro CONFIG+=debug
D:\Qt\Qt5.14.2\Tools\mingw730_64\bin\mingw32-make.exe -j4
```

在当前开发环境中，也可以用 VS Code 运行任务 `构建 simple_qt (Debug)`，然后选择 `调试 simple_qt (GDB)`。

## 默认连接地址

- 机械臂 TCP：默认 `192.168.5.1:6601`
- 设备信息 TCP：`192.168.1.8:25001`
- MQTT：优先 `192.168.1.8:1883`，连接失败时回退 `192.168.1.8:26001`
- FTP：`ftp://192.168.1.8:21/`，使用设备固件预置的本地 FTP 账号登录

使用 SSCOM 模拟机械臂时，可在界面中把机械臂地址改为 `127.0.0.1:9000`。

## 目录

- `src/`：C++ 后端与状态机
- `qml/`：主界面
- `grr20.lua`：与当前上位机协议匹配的机械臂 Lua 副本
- `.vscode/`：当前 Windows/Qt 环境的构建与调试任务

## 数据输出

- FTP 数据：`下载/SLAM_calibration/<设备采集目录>/`
- 任务结果：`文档/SLAM_calibration/results.csv`

`results.csv` 使用带 BOM 的 UTF-8，Excel 可以直接识别中文。

## 安全提示

机械臂程序启动时会先移动到 `P41`，沿用户坐标系以低速下降 230 mm 后才初始化并松开夹爪，再垂直上升恢复高度。首次上机必须先空载确认该下降位置有安全承接平面且路径无干涉。

实体机械臂首次联调前，应在空托盘、低速度和急停可用的条件下确认 2×3 托盘角点、扫码点上方 150 mm 的垂直抬升路径、抓取高度及整段轨迹。FTP 下载完成仅表示数据采集成功，不等于 SLAM 标定算法已经计算并通过精度验证。
